# Riverline 德州扑克 AI 教练 — 使用说明

Riverline 是一个德州扑克（NLHE）AI 教练应用：你在浏览器里构造一个牌局场景，应用会用规则引擎重放牌局、给出结构化分析、教学解释、练习题目，并可通过求解器引擎计算最优策略。

---

## 1. 快速开始（浏览器实测）

### 方式 A：Docker Compose 栈（推荐，一键）

```bash
docker compose up -d --build
```

- 前端：http://127.0.0.1:3000
- 后端 API：http://127.0.0.1:8000（健康检查 `/health`）
- 栈内自带：API、Web（静态构建）、Redis、Postgres、分析 worker、solver worker

### 方式 B：本地开发模式（改前端代码时用）

```bash
# 终端 1 — 后端（注意先清 PYTHONPATH，本机 Hermes venv 会污染）
unset PYTHONPATH
POKER_COACH_REDIS_URL=redis://127.0.0.1:6379/0 POKER_COACH_REDIS_WORKER_IN_PROCESS=1 \
  py -3.13 -m uvicorn poker_coach.api.app:app --app-dir backend --port 8000

# 终端 2 — Redis（如无 compose 栈）
docker run -d --rm --name poker-redis-verify -p 6379:6379 redis:7-alpine

# 终端 3 — 前端
cd frontend && npm run dev -- --hostname 127.0.0.1 --port 3000
```

> 起服务前若端口被占：`netstat -ano | grep ":3000\|:8000" | grep LISTEN` 找到残留进程后强杀（中断的 dev 会话会留孤儿进程）。

## 2. 界面导览

**顶栏四视图**（按使用顺序）：

| 视图 | 用途 |
|---|---|
| **Hand Lab** | 构造场景、推进牌局、分析/教学/练习/求解（默认） |
| **Solver** | 求解器工作区（任务状态、策略网格、组合检查器） |
| **Train** | 练习与复习 |
| **Library** | 场景库与策略目录 |

**Hand Lab 三栏布局**：

- **左栏**：场景编辑器（01）、场景历史（02B）、行动时间线
- **中栏**：牌桌（主视觉）+ 行动按钮条
- **右栏**：范围编辑器（02）、上下文信息

**底部结果工作区**：四个标签 —— Evidence（分析证据）、Coach（教学解释）、Practice（练习）、Solver（求解结果）。新结果到达时自动切换到对应标签。

## 3. 构造决策场景

### 3.0 全新的一把（默认起点）

打开应用（或点 **重置场景**）即是一把**全新的牌**：0 既定内容、0 输入、0 行动，只有小盲/大盲已经下注（底池 150、双方 10,000 筹码）。手牌、牌面都由你录入——填入 Hero 手牌后即可开始行动。复盘时对手手牌不知道也没关系（见 3.2）。

### 3.1 手牌输入（两种方式并存）

- **键盘输入**：直接在输入框输入，如 `As Kd`（大小写均可，两张牌用空格分隔）。
- **52 张选牌器**：点击输入框旁的 **「选牌」** 按钮，弹出 52 张牌面板；点一张牌即填入目标位置（手牌自动追加到空位、牌面直接填入该位置）。已被场景使用的牌会置灰不可选，避免同一张牌重复出现。Hero 手牌、Villain 手牌、5 个牌面位置（前 3 个为当前牌面，后 2 个为未来牌）各有独立选牌入口。

### 3.2 复盘模式（只填自己的手牌）

真实牌局复盘时，你往往**不知道对手的手牌**。勾选 **「复盘模式 · 只填自己的手牌（对手手牌未知）」**：

- Villain 手牌输入框被禁用并清空，显示「对手手牌未知（复盘模式）」；
- 场景中对手手牌为空，分析/教学会以"对手未知"的方式降级处理：
  - 分析：提示 villain 手牌与范围缺失、equity 不可用（这是**诚实降级**，不会伪造对手信息）；
  - 教学：给出基于你手牌与牌面的原则性解释；
  - 求解：需要你为双方显式提供范围（提交 Solver 时填写 hero/villain 范围即可）。

### 3.3 盲注与筹码

小盲 / 大盲 / 双方起始筹码均可调整。底池、有效筹码、SPR 由后端规则引擎从盲注与行动推导。

## 4. 推进牌局

行动按钮条始终显示**当前行动者**的合法动作（由后端规则引擎校验）：

- `Call 50` / `Check` / `Bet 200` / `Raise to …` / `All-in` / `Fold`
- 翻牌前结束后点 **`Deal flop`**（turn/river 同理），牌面来自你填的牌面输入。

每步操作会写入行动时间线；**「重新校验」** 让后端重新重放整手牌。`撤销 / 重做 / 重置场景` 管理编辑历史。

### 4.1 整手复盘工作流

整手复盘工作台围绕真实玩家行动运行，而不是只分析最后一个节点：

1. **追加行动并观察范围信念**：每次追加合法行动后，范围面板会跟随该行动者的 seat，自动请求该节点的 Range Belief。可用时显示 Prior / Current / Δ（底层按具体 combo 更新，界面聚合为 169 格）；没有精确 policy 时保留 Prior，并显示 `Current range unavailable` 和原因，不伪造 Current。
2. **选择历史行动**：点击行动时间线或整手复盘中的决策卡。系统同时保留两个游标：`eventSequence` 是行动已经发生后的序列，供行动后范围更新使用；`decisionSequence = eventSequence - 1` 是行动发生前的节点，供规则分析、教学和 Solver 使用。因而选中一手 `Bet` 时，Solver/分析看到的是下注前的牌面与范围，Range Belief 看到的是该行动造成的行动后变化；未来的 turn/river 牌不会泄漏到更早节点。
3. **按节点手动求解**：选中历史行动后，点击该行动的「提交 Solver」只提交这一点的 job。提交 gate 会逐项检查翻后（flop/turn/river）、恰好 2 位 active players，以及两位玩家范围是否就绪；不满足时会显示具体原因。job 按 `actionId` 和节点 fingerprint 独立保存，可排队、运行、取消和轮询。场景或节点改变后，不匹配的 job 会标为 stale，需要重新提交；系统不会自动为整手所有节点批量求解，这是为了避免未经用户选择的高成本任务和把不同节点结果混用。
4. **生成整手复盘**：点击「生成整手复盘」后，系统按真实玩家行动顺序展示逐决策卡、教学摘要、范围状态、Solver 状态和不确定性。整手总结只聚合这些节点已有事实；优先复盘点会带有对应 `actionId`，点击即可跳回该决策。已完成的牌局仍可回看此前的行动并生成复盘；若没有玩家决策，则显示空态。

## 5. 分析、教学、练习、求解

### 生成分析（Evidence）
点 **「生成分析」**：底池、跟注成本、SPR、底池赔率、手牌类型、outs、牌面纹理、equity 区间（hero vs villain）、范围对比、策略匹配等结构化证据。

### 教学解释（Coach）
点 **「教学解释」**：基于分析证据生成的中文教学讲解（本地教师引擎；配置外部 LLM 后为深度讲解）。回复包含证据约束、推荐动作与理由。

### 生成练习（Practice）
点 **「生成练习」**：围绕当前场景出题并即时评分。

### 求解（Solver）
在选中的行动前节点，右栏为双方填好范围（或选择默认范围）后点 **「提交 Solver」**：

- 仅支持 **翻牌后（flop/turn/river）且决策点恰好剩余 2 名玩家** 的场景（8-max 桌上剩 2 人同样可解；3 人及以上会明确提示不支持）；
- 求解任务经 Redis 队列交给 sidecar 引擎，结果包含策略网格（StrategyGrid）、组合检查器（ComboInspector）与节点导航（NodeNavigator）；
- 完整范围求解约 3–4 分钟，小范围约 1 分钟。

整手复盘中的 Solver 评估只使用与该 `actionId`、行动前 `decisionSequence` 和场景/节点 fingerprint 相匹配的已完成 job。实际行动状态按以下产品解释显示：

| 状态 | 含义 |
| --- | --- |
| `primary` | 实际行动是该节点最高频行动，显示「符合主策略」 |
| `mixed` | 不是最高频，但实际频率达到 5% 阈值，显示「可接受混频」 |
| `rare` | 实际频率大于 0 但低于 5%，显示「明显偏离常用策略」 |
| `absent` | 精确节点策略中频率为 0 或没有该行动，显示「Solver 不采用该行动」 |
| `unscored` | 没有 Solver、来源不匹配、节点不支持、缺少具体 combo 或 off-tree，显示「无 Solver 结论」 |

5% 是产品解释阈值，记录为 `product_interpretation`，不是扑克理论事实。下注尺寸不在 Solver tree 时可以显示 nearest-size 映射，但仍保持 `unscored`；无精确策略时也不会把 off-tree、no-policy 或 unavailable 说成错误。当前实现没有 action-specific EV loss 结论，因此整手教学明确不报告 EV 损失。

## 6. 范围编辑器

右栏 **Range** 面板：

- **169 格范围矩阵**：点击格子调整权重（`AA weight` 等按钮），支持折叠为紧凑摘要；
- **默认范围** 下拉：BTN open / BB defend / BB 3-bet / vs 3-bet / 4-bet 等常用预设；
- **标准化范围**：输入如 `22+, A5s+, K9o+` 后一键标准化；
- 范围侧切换：Hero 范围 / Villain 范围，双侧可重叠对比。

范围面板会在具备策略来源时显示 Prior / Current / Δ。内置翻前策略目前只覆盖严格的 8-max、全员 100BB、无 ante/无 rake、无人入池、2.5BB RFI（UTG 到 SB）节点；它是项目内置的 curated raise/fold 基线，不是 solver 频率。不同开局尺寸、BB option、limp 或面对加注/3-bet 时会明确显示没有可用 policy，不会用相近范围猜测。

选择历史行动后，范围面板显示选中行动者和对应的 `eventSequence` / `decisionSequence`；可用时 Current 是行动后的条件信念，Δ 保留被完全淘汰 combo 的负变化。场景编辑、载入、撤销或重做会使旧范围结果和整手复盘标为过期，直到重新取得与当前场景一致的结果。

8-max 场景下，策略匹配按你的位置（UTG / UTG+1 / MP / HJ / CO / BTN / SB / BB）给出对应的翻前知识（RFI、防守、对抗 3-bet）。

## 7. 保存与历史

- **保存场景**：存入场景库（左栏 02B），可随时 **历史**（查看分析历史）、**重新分析**、**复制**、**删除**；
- 每次分析自动产生版本（rev），支持版本对比（选择两个版本后比较分析差异）；
- **导入 JSON / 导出 JSON**：场景可序列化导入导出。

## 8. 已知边界与说明

- 复盘模式下对手手牌未知：equity 不可用是**有意为之**（不伪造对手信息），教学与策略匹配不受影响；
- 求解器为双人翻后引擎：多人底池与翻前求解不支持，界面会明确提示；
- 求解为近似解：有 bunching 忽略等教学性近似，求解结果的策略网格以组合频率展示，供学习参考而非绝对真理；整手复盘不会自动批量提交 Solver。
- 整手复盘的每张决策卡只使用行动前快照和该节点自己的证据；无手牌、无 policy、无 grounded job、off-tree 或 provenance 不匹配时会显示 warning / unavailable / unscored，并保留原则性教学，不补猜策略或 EV 损失。
- 内置 `preflop_policy` 仍只覆盖 8-max、100BB、no-ante/no-rake、无人入池、2.5BB RFI（UTG 到 SB）curated raise/fold 基线；BB option、limp、不同 open size、面对 open/3-bet/4-bet、ante/rake/stack 变体，以及 multiway Solver 仍不支持。
