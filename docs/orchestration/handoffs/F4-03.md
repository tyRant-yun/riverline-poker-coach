## Time and recovery evidence

The projector calls the existing event validator before writing a review. It produces nothing without a final `hand_completed`, and a post-completion event is rejected as `invalid_event_stream`. Each hero decision preserves only event IDs, board cards, and action count from the strict prefix before that hero action; it therefore cannot see terminal settlement or later events.

`ProjectionRunner` records the F1-04 per-hand cursor, while the SQLite review table has a unique `(session_id, hand_id, hero_seat)` key. The focused restart test closes/reopens both stores, appends the terminal event, then verifies a repeated delivery returns the same record and the table contains one row.
